# shulker

> **Shrinks, speeds up, and scrambles Bedrock resource packs — squashing is the product, obfuscation falls out of it.**

`shulker` is an optimizer for Minecraft Bedrock Edition (MCBE) resource packs.
Bedrock servers ship the entire resource pack to every client on join, unencrypted —
so pack size *is* join time. `shulker` rewrites packs so they download faster, load
faster, and are harder to casually rip, while guaranteeing the pack loads
**exactly the same** in the game.

- **Single static binary**, zero cgo, zero dependencies (Go 1.22+)
- **Byte-deterministic**: same input + same config = byte-identical output
- **Refuses to ship what it cannot prove**: every squash is re-loaded and
  re-validated before it exists

```
$ shulker squash MyPack.mcpack

  category           before       after       saved  saved %
  ----------------------------------------------------------
  json-registry      4.2 KiB      2.4 KiB     1.8 KiB    43.5%
  json               5.4 KiB      3.6 KiB     1.8 KiB    33.2%
  textures           2.5 KiB      2.5 KiB       0 B     0.0%
  ...
  ----------------------------------------------------------
  TOTAL             13.7 KiB     10.1 KiB     3.6 KiB    26.3%
  47 files in, 47 files out

  renamed 23 files, rewrote 30 references, re-encoded 0 PNGs
```

## Install

Build from source (the only supported path for now):

```
git clone <this repo> && cd shulker
make build          # or: go build -o shulker ./cmd/shulker
```

CI builds and tests every push (Go build + vet + race tests + golangci-lint).

## Usage

```
shulker squash <in> [out]     squash a pack (.mcpack/.zip file or directory)
shulker check <pack>          validate a pack without changing anything
shulker map <mapping.json>    inspect a squash mapping
                              --reverse <pack> <outdir>: re-derive original layout
shulker regolith              Regolith filter mode (Regolith invokes this)
```

`shulker squash` flags: `--no-rename`, `--no-rename-textures`,
`--no-rename-sounds`, `--no-rename-identdirs`, `--no-minify`, `--no-png`,
`--workers N`, `--out-map FILE`, `--report FILE`, `--no-cache`, `-q`.

Every squash writes a **mapping file** (default `<out>.map.json`) recording every
rename and every reference rewrite. Keep your original pack as the source of
truth; the squashed artifact is a build output, never something you hand-edit.
`shulker map --reverse <mapping> <pack> <outdir>` rebuilds the original layout
from a squashed pack (minified JSON and re-encoded PNGs honestly stay built —
the original pack remains the source of truth for those).

## Measured results (honest numbers, enforced in CI)

The fixtures under `testdata/benchmarks/` are deterministic and generated by
`testdata/gen`, and `TestBenchmarkFixtureReductions` asserts the thresholds on
every CI run — these numbers cannot silently rot:

| Fixture | Models | Before | After | Saved |
|---|---|---|---|---|
| `json_heavy` | author-formatted JSON: comments, 4-space indent, trailing commas, BOMs, float noise | 59.0 KiB | 41.7 KiB | **29.3%** |
| `png_heavy` | 24 BestSpeed-encoded 128×128 sprites (community-tool style) | 27.8 KiB | 21.4 KiB | **23.0%** |

Notes, honestly:

- The JSON savings come from comments/whitespace/BOM stripping, float-noise
  normalization (`0.07000000000000001` → `0.07`, which vanilla's own
  `sound_definitions.json` is full of), and shorter renamed paths.
- The PNG savings come from re-encoding at maximum compression,
  keep-if-smaller, **without quantization** (deliberately out of scope in
  v0.1). Already-well-compressed PNGs gain ~0% — that is the keep-if-smaller
  guard doing its job.
- `.ogg` audio is passed through byte-for-byte (the engine requires Vorbis;
  there is no good pure-Go encoder). A stub hook exists for a future optional
  ffmpeg pass.
- Zip entries use DEFLATE for JSON/text/lang and STORE for already-compressed
  payloads (`.png`/`.ogg`/`.jpg`) — deflating them twice is pure CPU waste on
  the join path. TGA is the one image exception (it compresses well).

## How it works

1. **Load** — `.mcpack`/zip/directory inputs, nested single-directory zips
   handled, world templates and addon bundles rejected with actionable hints,
   manifests validated (never modified — stored verbatim, byte-identical).
2. **Parse + index** — every JSON file is parsed with shulker's own
   order-preserving parser, which accepts exactly what the Bedrock engine
   accepts: `//` and `/* */` comments, trailing commas, UTF-8 BOMs, duplicate
   keys. Key order is preserved; untouched tokens re-encode byte-identically.
3. **Reference graph** — every file type the engine resolves is modeled:
   terrain/item atlases (all four vanilla value shapes), flipbook textures,
   `*.texture_set.json` (Vibrant Visuals MERS), blocks.json short-name chains,
   sound_definitions + sounds.json event indirection, client entities,
   attachables, legacy AND modern geometry, animations, animation/render
   controllers, particles, materials, json-ui, and textures_list.json. Every
   edge carries file + JSON pointer + the exact authorial form of the
   reference.
4. **Transform** — flag-gated passes:
   - *JSON minify*: compact re-encode, key order preserved, Molang untouched,
     float noise normalized only when provably value-identical at float32
     (the engine reads floats as 32-bit).
   - *Path renaming*: a file is renamed only if **100% of its inbound
     references live inside this pack and every one of them gets rewritten**
     — plus a vanilla-sensitive deny-list, PBR-set lockstep, blocker tracking
     for unknown-schema references, and conventional suffix preservation
     (`pig.geo.json` stays `*.geo.json`). Short generated paths
     (`textures/_0.png` style; the `_` prefix dodges vanilla paths).
   - *PNG optimize*: decode + re-encode at best compression, keep-if-smaller,
     alpha/palette preserved; only textures whose references are provably
     pack-internal are ever re-encoded — vanilla-override textures keep their
     exact bytes.
5. **Validate before shipping** — the output is re-loaded as a real pack,
   re-parsed, re-graphed, and structurally diffed against the input with an
   allowlist built from the transform's own log: a squash may only change
   what it said it changed. Manifest byte-identity, inventory accounting,
   reference-continuity, PBR lockstep, and deny-list immutability are all
   checked. If any check fails, nothing is written and the reasons are
   printed with file + JSON pointer context.

Determinism: fixed 1980-01-01 zip timestamps, sorted entries everywhere,
sorted iteration instead of map order, no wall-clock or machine data in
artifacts. Re-squashing unchanged assets is instant thanks to a
content-addressed cache (`~/.cache/shulker`, `--no-cache` to disable), and
cached output is byte-identical to fresh output — determinism makes that
provable, and there's a test that proves it.

## Regolith filter mode

`shulker` runs as a Regolith exe filter. The contract was verified against
[Regolith 1.8.0](https://github.com/Bedrock-OSS/regolith) source and a live
`regolith run` (see `docs/REGOLITH.md` for the verification log and the exact
project layout):

```jsonc
// config.json
{
  "name": "my-project",
  "author": "you",
  "packs": { "behaviorPack": "BP", "resourcePack": "RP" },
  "regolith": {
    "formatVersion": "1.2.0",
    "dataPath": "data",
    "filterDefinitions": {
      "shulker": { "runWith": "exe", "exe": "shulker.exe" }
    },
    "profiles": {
      "default": {
        "filters": [
          { "filter": "shulker", "settings": { "no-rename": false } }
        ],
        "export": { "target": "none" }
      }
    }
  }
}
```

Put `shulker.exe` in the project root next to `config.json`. Settings map onto
squash flags: `no-rename`, `no-rename-textures`, `no-rename-sounds`,
`no-rename-identdirs`, `no-minify`, `no-png`, `no-cache`, `workers`.

## FAQ

### Is this DRM?

**No.** Everything shulker does is trivially reversible by a determined
actor, and it does not try to change that:

- Bedrock sends the entire pack to clients **unencrypted**. Anyone can open a
  `.mcpack` — it's a zip. shulker does not, and cannot, change this.
- What shulker *does* do: strip comments and whitespace, shorten file paths,
  and re-encode PNGs. That removes low-effort "browse the folder and recognize
  everything" ripping, and the mapping file that restores original names stays
  **with you**, the creator.
- What it does *not* prevent: anyone extracting the pack, viewing textures,
  re-deriving structure, or using the assets. If someone wants your art, they
  can get it. This is a speed + size tool with mild anti-casual-ripping as a
  side effect — positioned honestly.

### Will it break my pack?

The design bet is conservatism: every transform is either provably safe (the
validator proves it, mechanically, on every squash) or it is skipped with a
logged reason. Files are renamed only when every inbound reference is visible
inside the pack and gets rewritten; anything ambiguous stays untouched. If
shulker ever finds something it cannot fully understand, it fails loudly with
file + JSON pointer context instead of guessing. The worst case is "shulker
refused and told me why," never "shulker corrupted my pack."

### Why is my `textures/blocks/stone.png` not renamed?

It's a vanilla path: the engine (and vanilla-side JSON you can't see) may
resolve it by its exact location. shulker renames only files whose references
are provably pack-internal. Classic override textures keep their paths and
their exact bytes. See [docs/INVARIANTS.md](docs/INVARIANTS.md) for the full
policy.

### Why were my PBR textures (`_mer`, `_normal`, `_heightmap`, `_mers`) renamed together or not at all?

PBR companions are found by suffix convention next to the color map — there is
no JSON tying them together. Renaming the color map without its companions
silently breaks rendering, so sets move in lockstep (suffix and each file's
own extension preserved, mirroring vanilla's `.png` color + `.tga` companion
mixes) or not at all.

### What if I find a bug?

`shulker check <pack>` tells you exactly what it sees, with file + JSON
pointer context. A failed post-transform validation is a shulker bug — the
error says so, and issues are welcome. Your original pack is never modified:
squash writes a new file and never touches its input.

## Manual smoke test (5 minutes, in-game)

You cannot prove a Bedrock pack loads by staring at JSON — here is the quick
human check after squashing a real pack:

1. `shulker squash MyPack.mcpack` → note the `TOTAL` line and that
   `shulker check MyPack.squashed.mcpack` passes.
2. Copy the squashed pack to `com.mojang/resource_packs/` (or serve it from
   your server) and enable it on a world **with the matching behavior pack
   linked by UUID** (the manifest is byte-identical, so linkage is preserved).
3. In game, check: a custom block's texture renders; the custom mob renders
   with all its skins; an animated (flipbook) block animates; the custom
   json-UI screen opens with its textures; your sounds play; PBR/RTX renders
   if applicable.
4. Join time is the demo: compare the world's resource-pack download bar
   before and after.

## Limitations (v0.1)

- `.mctemplate` / `.mcaddon` / world containers are rejected (extract the RP
  and squash that). Behavior packs are out of scope. `subpacks/` is left
  completely untouched (with a warning).
- Molang is never altered (v0.1 builds the tokenizer seam only).
- No texture atlas packing, no audio re-encoding, no PNG quantization — see
  the [roadmap](docs/ROADMAP.md).
- Audio (`.ogg`) and lang files pass through byte-for-byte; TGA/JPG pass
  through (only PNG is re-encoded).
- The vanilla-path deny-list is a curated conservative approximation; a
  generated frozen vanilla path list is on the v0.2 roadmap.
